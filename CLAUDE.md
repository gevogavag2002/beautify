# Beautify — mobile app

Booking app for beauty providers (barbers, nail artists, etc.). Clients send booking
requests, providers accept/decline. Two roles inside one app: **client** and **provider**.
Backend (Laravel) and web (Vue 3) are built by Armen in separate repos; this repo is the
Expo / React Native mobile app only.

Design source of truth: the Claude Design canvas
https://claude.ai/artifact/4bB9fUGV8CR9wRwV9C3fUU (read it with the Artifact tool, screens are
separate `*.dc.html` files inside it). Never invent UI; take it from the canvas.

## Stack (fixed, do not swap without the team's decision)

- Expo SDK 58, React Native, TypeScript strict, **pnpm** (`pnpm install`, `npx expo install <pkg>`)
- **Expo Router** (file-based routes in `app/`), typed routes on
- **NativeWind 4** (Tailwind 3 classes via `className`) for styling
- TanStack Query for server state, Zustand for global client state (session, role, theme)
- axios through the single instance in `src/services/axiosInstance.ts`
- i18n via i18next (`src/i18n`, `src/locales`)

## Architecture

Read `.claude/rules/architecture.md` before creating or moving any file, and
`.claude/rules/mocks.md` before adding any screen or API call. In short:

```
app/          routes only (thin files that render a screen from src/features)
src/
  features/   one folder per domain: auth, booking, schedule, search, profile, ...
  components/ui      base primitives on design tokens (Button, Input, Text, Card, Sheet)
  components/common  shared composite components (not tied to a feature)
  api/        axios calls grouped per domain object (authApi, bookingsApi, ...)
  services/   axiosInstance, notifications, storage
  store/      zustand stores (global only)
  hooks/      shared hooks
  theme/      design tokens (tokens.js is the single source, also feeds tailwind.config.js)
  mocks/      mock handlers + JSON seed data; every screen ships with its mocks (rules/mocks.md)
  utils/, constants/, types/, i18n/, locales/, providers/
assets/fonts  Nunito
```


Run `pnpm typecheck` before saying a change is done.

## Way of working

- Build screen by screen, confirm with the user before starting the next part.
- Explain trade-offs before introducing a new library; ask before adding native modules
  (they force a move from Expo Go to a development build).
- Language with the user: Russian. Code, comments, commit messages: English.
- **Docs move with the code.** Every change that adds, finishes or alters a screen, an
  endpoint, a stub, a command or a convention also updates the matching text in the same
  change: `docs/BACKLOG.md` (status, deferred, contract notes), `README.md`,
  `.claude/rules/*`, `.claude/skills/*`, and this file. A task is not done while the docs
  describe the old state.

## Running on the phone (Android, no cable)

- Dev client APK is built locally: `pnpm android:apk`, result in
  `android/app/build/outputs/apk/debug/app-debug.apk`. Send it to the phone (Telegram), install.
  Rebuild only when native deps or app.json change.
- Daily: `pnpm start`, then in the Beautify dev app on the phone enter
  `http://<laptop-lan-ip>:8081` (same Wi-Fi). Code changes hot-reload.
- `android/` is generated by prebuild and git-ignored; never edit it by hand, change
  app.json or config plugins instead.

## Backlog and stubs

`docs/BACKLOG.md` holds the status, every deliberately stubbed piece of UI, and the backend
contract notes for Armen. Whenever you stub something ("to be added later", a disabled link,
a fixed value like `+374`), add a row there in the same change; when you finish one, remove
the row. Read it at the start of a session to know what is left.

## Git

- **Never commit or push without the user's explicit permission in the current conversation.**
  Finish the work, run `pnpm typecheck`, report what changed, and wait. Permission for one
  commit does not carry over to the next one.

## Troubleshooting

- **className styles stop applying (NativeWind)**: pnpm may keep two copies of
  `react-native-css-interop` after dependency changes; styles get registered in one copy and
  read from the other. Check `ls node_modules/.pnpm | grep css-interop` (must be one line), run
  `pnpm dedupe && pnpm prune`, kill the old Metro by the PID on port 8081
  (`ss -ltnp | grep 8081`), then `pnpm start --clear`.
- Metro is started by `node .../expo/bin/cli start`; `pkill -f "expo start"` does not match it.
